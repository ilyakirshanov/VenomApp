# VenomApp 
Это мой проект, в котором я написал уязвимое веб-приложение, а потом исправлял уязвимости, записывая изменения на Github, используя CI пайплайн с настроенным SAST & DAST. 

Это веб-приложение я написал, вдохновляясь лабораторными на Portswigger, пытаясь реализовать похожую логику, но при этом получить опыт разработки веб-приложений. Конечно, я бы мог развернуть OWASP Juice Shop, но он более громоздкий и сложный, к тому же мне хотелось написать приложение самому. Пользовательский интерфейс предоставляет возможность просматривать посты, которые сделал администратор. Доступен вход на сайт, пользователь может зарегистрироваться и войти, в таком случае ему предоставляется функционал смены пароля и эл. почты. У администратора также есть возможность создания постов с изображениями и подписью к ним и возможность удаления аккаунтов пользователей.

## Стек технологий

- Бэкенд: Python 3.12, Flask, SQLite3
- Фронтенд: HTML, CSS, JavaScript  **(Изначальная уязвимая версия написана ИИ, так как у меня мало опыта во фронтенде)**
- Безопасность: Semgrep (SAST), OWASP ZAP (DAST)
- CI/CD: GitHub Actions
- Контейнеризация: Docker, Docker Compose

## Функционал

- Просмотр постов (без авторизации)
- Регистрация и вход
- Смена пароля и эл. почты в профиле пользователя
- Админ-панель:
  - Создание постов с изображением и подписью
  - Удаление пользователей
- Загрузка и отображение изображений

## Уязвимости (ветка vulnerable)

В исходной версии приложения были заложены следующие уязвимости:

- SQL-инъекция (login, profile)
- XSS (stored, DOM)
- Path Traversal
- IDOR 
- SSRF
- XXE
- File Upload
- Hardcoded Secret


## Исправления

Все перечисленные уязвимости были исправлены в ветке fixes. Каждое исправление закоммичено отдельно с соответствующим описанием. Финальная (условно) защищённая версия находится в ветке main. Хочу отметить, что приложение нельзя назвать на 100% защищенным, некоторые слабости опущены в виду учебной специфики проекта.

## CI/CD пайплайн (GitHub Actions)

Пайплайн описан в .github/workflows/ci.yml и работает так:

1. SAST (Semgrep) - запускается при каждом пуше в любую ветку. Ищет уязвимости в коде по правилам OWASP Top 10. 
2. DAST (OWASP ZAP Full Scan) - запускается при пуше в vulnerable и main, а также при Pull Request в main. Поднимает контейнер с приложением через Docker Compose, сканирует его на наличие уязвимостей.

После каждого запуска в артефактах сохраняются отчёты в формате JSON.

Результаты сканирования вынесены в отдельный раздел.

## Threat Modelling

В проектировании изначального приложения и дальнейшем исправлении уязвимостей я опирался на Threat Modelling по методу STRIDE + DREAD и на некоторые практики безопасной разработки, описанные в ГОСТ Р 56939-2024 (учитывая учебный характер проекта, методология модели угроз и реализация практик из ГОСТ Р 56939-2024 осуществлена выборочно).

## Ветки на Github

- vulnerable - исходная уязвимая версия (baseline для сканирования)
- fixes - ветка с коммитами-исправлениями (по одной уязвимости на коммит)
- main - финальная защищённая версия (результат работы)
